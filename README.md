# Индивидуальная работа по дисциплине «Новые языки программирования»

## 1. Многопоточность

### 1.1. Параллельное построение гистограммы байтов
**Язык:** Rust

**Постановка:** Разработать программу для подсчёта количества вхождений каждого из 256 возможных значений байта в бинарном файле. Обработка файла должна выполняться несколькими потоками, которым распределяются непересекающиеся части данных. После завершения работы потоков программа объединяет полученные частоты и выводит итоговую гистограмму. Результат не должен зависеть от количества потоков.

### 1.2. Моделирование клеточного автомата
**Язык:** Kotlin

**Постановка:** Реализовать многопоточную симуляцию клеточного автомата «Игра Жизнь» Конвея на прямоугольном поле. Состояние каждой клетки в новом поколении определяется числом живых соседей: живая клетка сохраняется при двух или трёх соседях, мёртвая оживает при трёх. Вычисления для разных участков поля выполняются параллельно, при этом все клетки очередного поколения должны рассчитываться по одному и тому же предыдущему состоянию. Клетки за границами поля считаются мёртвыми.

### 1.3. Параллельный поиск самого длинного возрастающего участка
**Язык:** Scala

**Постановка:** Написать программу, находящую самый длинный непрерывный строго возрастающий участок массива целых чисел. Массив разделяется на фрагменты для параллельной обработки. При объединении результатов необходимо учитывать участки, проходящие через границы фрагментов. Программа определяет длину участка и его начальную и конечную позиции; если подходящих участков одинаковой длины несколько, выбирается самый левый.

### 1.4. Поиск дубликатов файлов по контрольным суммам
**Язык:** D

**Постановка:** Разработать программу для поиска файлов с одинаковым содержимым в указанном каталоге и его подкаталогах. Проверка файлов организуется параллельно: сначала кандидаты группируются по размеру, затем для них вычисляются контрольные суммы. Файлы с совпадающими размером и суммой дополнительно сравниваются побайтово, чтобы исключить ложные совпадения. Результат представляет собой группы путей к файлам-дубликатам.

## 2. Алгоритмические задачи

### 2.1. Рекурсивная генерация разбиений числа
**Язык:** Haskell

**Постановка:** Реализовать рекурсивную программу, перечисляющую все способы представить заданное натуральное число в виде суммы положительных целых слагаемых. Порядок слагаемых не должен создавать новых вариантов: например, `3 + 1` и `1 + 3` считаются одним разбиением. Программа выводит все уникальные разбиения и их общее количество.

### 2.2. Поиск мостов в графе
**Язык:** OCaml

**Постановка:** Разработать программу для поиска всех мостов в неориентированном графе без петель и кратных рёбер. Мостом считается ребро, удаление которого увеличивает количество компонент связности. Программа должна обрабатывать в том числе несвязные графы и выводить все найденные мосты. Поиск реализуется с использованием рекурсивного обхода графа в глубину.

### 2.3. Рекурсивный разбор арифметических выражений
**Язык:** Prolog

**Постановка:** Реализовать собственный рекурсивный разбор и вычисление арифметических выражений, содержащих неотрицательные целые числа, операции `+`, `-`, `*`, `/` и круглые скобки. Программа должна учитывать приоритет операций и вложенность скобок, а операции одинакового приоритета выполнять слева направо. Унарные знаки не поддерживаются. При неправильной записи выражения или делении на ноль необходимо сообщать об ошибке без использования готового вычислителя строковых выражений.

### 2.4. Проверка изоморфизма деревьев
**Язык:** Julia

**Постановка:** Создать программу для проверки изоморфизма двух корневых бинарных деревьев без значений в узлах. Деревья считаются изоморфными, если одно можно преобразовать в другое перестановками левого и правого поддеревьев отдельных узлов. Проверка должна выполняться рекурсивным сравнением структуры деревьев с учётом обоих возможных порядков потомков. Программа сообщает, изоморфны ли заданные деревья.

## 3. Ввод/вывод в консоль и файл

### 3.1. Внешняя сортировка большого файла
**Язык:** Perl

**Постановка:** Реализовать сортировку текстового файла, содержащего по одному целому числу в строке, без загрузки всего файла в оперативную память. Программа последовательно сортирует ограниченные по размеру фрагменты, сохраняет их во временные файлы и объединяет отсортированные фрагменты в единый результат. В памяти одновременно должно находиться не более установленного объёма данных; программа должна работать и с файлами, значительно превышающими этот объём.

### 3.2. Сравнение бинарных файлов
**Язык:** Ruby

**Постановка:** Написать программу для побайтового сравнения двух файлов любого типа. Файлы читаются последовательно небольшими блоками, без полной загрузки в память. Если содержимое совпадает, программа сообщает об идентичности; иначе указывает позицию первого отличающегося байта и размеры файлов. Различия длины также должны корректно определяться.

### 3.3. Слияние журналов по временным меткам
**Язык:** Lua

**Постановка:** Разработать программу для объединения двух текстовых журналов событий, строки которых уже упорядочены по временным меткам формата `YYYY-MM-DDTHH:MM:SSZ`. Программа должна сформировать общий журнал в хронологическом порядке, сохранив все исходные записи. При равных метках первыми размещаются записи из первого файла. Слияние выполняется последовательным чтением, без загрузки журналов целиком в память.

### 3.4. Построение указателя слов с номерами строк
**Язык:** F#

**Постановка:** Реализовать программу, которая анализирует текстовый файл и формирует алфавитный указатель встречающихся слов. Для каждого слова необходимо указать номера строк, в которых оно встречается. Регистр букв игнорируется; если слово встречается в одной строке несколько раз, номер строки указывается только один раз. Результат сохраняется в отдельный текстовый файл.

## 4. Клиент-серверное взаимодействие

### 4.1. Сервер бронирования временных интервалов
**Язык:** Erlang

**Постановка:** Разработать TCP-сервер и клиент для бронирования временных интервалов отдельных ресурсов, например переговорных комнат. Клиент может создать бронирование, просмотреть занятые интервалы и отменить существующую бронь. Сервер хранит сведения о бронированиях и запрещает пересекающиеся по времени интервалы для одного ресурса; соприкасающиеся границами интервалы допустимы. При одновременных обращениях нескольких клиентов необходимо исключить конфликтующее бронирование одного и того же времени.

### 4.2. Сервер RLE-сжатия
**Язык:** Elixir

**Постановка:** Реализовать TCP-сервер и клиент для сжатия и восстановления данных методом Run-Length Encoding (RLE). Клиент передаёт последовательность байтов в шестнадцатеричной записи и выбирает операцию сжатия или распаковки. При сжатии последовательные одинаковые байты представляются парами «количество повторений — значение байта», а при распаковке восстанавливается исходная последовательность. Сервер должен корректно обрабатывать пустые данные и ошибочные последовательности.

### 4.3. Сервер аренды ресурсов
**Язык:** Groovy

**Постановка:** Создать TCP-сервер и клиент для учёта выдачи ограниченного набора ресурсов, например оборудования. Клиент может запросить список ресурсов, арендовать свободный ресурс на своё имя и вернуть ранее арендованный. Каждый ресурс в один момент времени может принадлежать только одному клиенту; вернуть его может только текущий владелец. Сервер должен сохранять согласованность состояния при одновременных запросах нескольких клиентов.

### 4.4. Сервер вычисления контрольных сумм
**Язык:** Nim

**Постановка:** Разработать TCP-сервер и клиент для вычисления контрольной суммы CRC32 переданных данных. Клиент отправляет байтовую последовательность в шестнадцатеричной записи, сервер проверяет корректность данных, вычисляет стандартную CRC32 и возвращает её в виде восьмизначного шестнадцатеричного числа. Для одинаковых данных результат должен быть одинаковым независимо от клиента; некорректные запросы должны обрабатываться без остановки сервера.

## 5. Конвертация данных из одного формата в другой

### 5.1. JSON → Graphviz DOT
**Язык:** Swift

**Постановка:** Реализовать конвертер описания ориентированного графа из JSON в текстовый формат Graphviz DOT. В JSON задаются вершины с идентификаторами и подписями, а также направленные рёбра между ними. Программа должна проверять корректность ссылок на вершины и формировать DOT-документ с описанием узлов и связей, пригодный для визуализации средствами Graphviz.

### 5.2. Журнал Apache → CSV
**Язык:** Clojure

**Постановка:** Разработать программу для преобразования журнала HTTP-запросов Apache из формата Common Log Format (CLF) в CSV. Из каждой корректной строки журнала извлекаются IP-адрес, время запроса, HTTP-метод, путь, код состояния и размер ответа. Полученные значения записываются в таблицу с заголовками; текстовые значения экранируются по правилам CSV. Некорректные строки не должны прерывать обработку всего файла.

### 5.3. PGM → текстовая графика
**Язык:** Common Lisp

**Постановка:** Создать конвертер изображения в оттенках серого из текстового формата PGM P2 в символьное представление (ASCII-art). Программа читает размеры изображения и значения яркости пикселей, затем заменяет каждый пиксель символом из заранее заданной шкалы плотности — от тёмных символов до пробела. Полученное текстовое изображение сохраняет количество строк и столбцов исходного изображения. Должны поддерживаться комментарии в PGM-файле.

### 5.4. SQL INSERT → CSV
**Язык:** Scheme

**Постановка:** Разработать конвертер записей из SQL-операторов `INSERT INTO ... VALUES ...` в CSV-файл без подключения к базе данных. Программа обрабатывает один или несколько операторов для одной таблицы с одинаковым набором столбцов, извлекая имена колонок и значения записей. Поддерживаются целые числа, строки в одинарных кавычках с экранированием апострофов удвоением и `NULL`. Разбор должен отличать разделительные запятые от запятых внутри строк, а результат — соответствовать правилам CSV.
